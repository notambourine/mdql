# mdql

Schema-driven typed CRUD + full-text search + wiki graph over markdown files with YAML frontmatter. One binary, one `schema.yml`, a directory of notes. Extracted from `notambourine/crm-cli` as a clean hat-tip (fresh git history, not a fork).

## Design principles

- **Token-respectful output**. mdql is primarily consumed by agents. Keep `--help`, error messages, lint output, and `list`/`show` rendering terse. No preamble, no ASCII art, no duplicated column headers. One line per flag. Prefer `--format json` for agent paths. The agent token budget is a user-facing concern — treat verbose output as a bug.
- **Schema is the single source of truth**. Never hardcode entity kinds; iterate `schema.Entities`. Never maintain a parallel `Dirs`/`Kind*` list.
- **Generic over typed**. One `Create(kind, map[string]any)` beats five `CreatePerson/CreateOrg/…`.
- **Pipe over aggregate**. No in-code pipeline/overdue/context logic — users pipe `list --format json` through `jq`. Recipes live in `queries.md` (consumer-side).

## Settled decisions

1. Clean hat-tip, not fork. LICENSE + README credit `jdanielnd/crm-cli`.
2. Name: `mdql` (mdgraph/mdbase/mdschema are taken).
3. Schema format: YAML (reuses `gopkg.in/yaml.v3`).
4. Drop CRM-only behaviors: no pipeline aggregation, no context briefing, no overdue filter, no duplicate-email logic in code.
5. Module path: `github.com/notambourine/mdql`.
6. **Filename is canonical id.** mdql does not auto-inject `id`, `uuid`, `created_at`, or `updated_at` into frontmatter. The slug is derived from the filename on read (injected into the in-memory record as `id`). User-declared timestamp fields are honored as normal data; mdql doesn't manage them. Slug collisions get suffixed at the filename level (`jane-smith`, `jane-smith-2`).
7. **`mdql schema describe --format json` is the agent session-entry payload.** Single command emits the full entity/field/command graph an LLM needs to derive valid commands. Stable JSON shape — integration test pins it. Always JSON; `--format` is ignored.
8. **`wiki dangling` and `wiki orphans` return `[]` not `null` on empty result** — `jq 'length'` works without nil-handling.
9. **Wiki link grammar is three forms.** `[[slug]]` (entity), `[[kind/slug]]` (kind-qualified entity), `[[parent-slug/sub-dir/sub-slug]]` (sub-file path — uses SubFile.Dir, not the sub-kind name). In-frontmatter link `target:` uses `.` for sub-file kinds (`project.decision`); in-body refs use `/` with sub-file Dirs. `ExpandLinkKeys` fans multi-segment refs so `backlinks <parent>` surfaces everything pointing into the parent, full-form and sub-file-grain alike.
10. **Sub-files index as first-class bleve docs.** Doc.Type = sub-kind (so `search --type meeting` hits sub-files directly); ParentKind/ParentSlug/SubKind carry the rest. Sub-file LinksTo always includes the parent slug, keeping parents reachable even when a sub-file only links to siblings. Entity archive cascades: removing a parent deindexes its sub-files.
11. **Dry-run writes are Plan* siblings, not dryRun bool parameters.** `PlanCreate/PlanUpdate/PlanArchiveEntity` (and sub-file variants) share a `prepareX` helper with their executing twin so validation, slug/path resolution, and doc construction live in one place. The executing method runs the shared prep, then performs `writeEntity + indexer.Upsert`; the Plan method runs the prep and returns a `WritePlan`. Signatures of the existing write methods stay untouched — no test churn. `WritePlan.Path` / `ToPath` are root-relative so goldens stay stable across tempdirs. Plan carries a `Before` snapshot for update/archive/delete.
12. **Schemaless cwd emits an onboarding goldenset, not an error.** `mdql` with no `./schema.yml` and no explicit `--schema` flag writes `engine/onboarding.md` (embedded via `//go:embed`) to stdout and exits 0. The doc is the full agent onboarding surface: type grammar, wiki link forms, command map, `--dry-run`/`--fields`, and a bootstrapping prompt pushing the agent to explore the repo and propose a schema rather than auto-scaffolding a preset. Explicit `--schema /missing.yml` still errors — the no-schema path only fires when the user gave no indication of intent. `engine/onboarding_test.go` pins the markers the goldenset must contain.
13. **Auto-sync-on-open keeps the bleve index self-healing.** Every command that opens the store runs `Store.SyncIfStale` before serving queries: `WalkDir` the store comparing `.md` mtimes against `<runtime_dir>/sync.json:last_indexed_at`, short-circuit on first file newer than the stamp, trigger `Reindex` if dirty. Fixes the three external-write drift cases — `git pull`, hand-edit in Vim, fresh clone with empty index. Write-through via `Create`/`Update` remains the fast path (Upsert is idempotent, so sync is a no-op on mdql's own writes). `--no-sync` global flag bypasses the check for tight scripting loops. Walk excludes `runtime_dir` and `archive_dir` to avoid infinite loops and stale-archive re-indexing. `sync.json` is mdql's own file — separate from Bleve's internal `index_meta.json`. `MarkSynced()` is called post-`init` so fresh stores don't trigger a pointless rebuild on first command.
14. **Body input has three sources: `--body`, `--body-file <path>`, `--body-file -` (stdin).** All resolve to the same `body` key in the input map; `--body` and `--body-file` are mutually exclusive (cobra `MarkFlagsMutuallyExclusive`). Motivation: agents pulling email bodies / call transcripts from MCP tools cannot reliably pass multi-line content with backticks/quotes through inline `--body "..."` shell quoting. Resolution happens in `flagBindings.resolveBody` so create + update + sub-file create + sub-file update share one read path. `collect`/`collectAll` therefore return `(map, error)` — every call site propagates the error so a missing path or unreadable stdin surfaces to the user instead of writing an empty body. `engine/onboarding_test.go` pins `--body-file` as a required marker so the doc never drifts away from the flag.
15. **Release pipeline: tag push → goreleaser → homebrew tap.** `v*` tags on `notambourine/mdql` fire `.github/workflows/release.yml`, which runs goreleaser to cross-compile darwin/linux × amd64/arm64, publish a GitHub Release with checksums, and auto-commit `Formula/mdql.rb` to `notambourine/homebrew-tap` via `HOMEBREW_TAP_GITHUB_TOKEN` (fine-grained PAT, Contents: RW, scoped to the tap repo). End-users install with `brew tap notambourine/tap && brew install mdql`. Cutting a release is one command: `git tag vX.Y.Z && git push origin vX.Y.Z`. Build info (`version`/`commit`/`date`) is injected via `-X main.version=…` ldflags and surfaces through `mdql --version` — which short-circuits schema load so it works in any cwd.
